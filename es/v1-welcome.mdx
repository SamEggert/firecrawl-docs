¡Firecrawl V1 ya está aquí! Con esto presentamos una API más confiable y fácil para desarrolladores.

Novedades:

* Formatos de salida para `/scrape`. Elige en qué formatos quieres el resultado.
* Nuevo [endpoint `/map`](/es/features/map) para obtener la mayoría de las URL de una página web.
* API más amigable para el estado de `/crawl/{id}`.
* Límites de tarifa 2x para todos los planes.
* [Go SDK](/es/sdks/go) y [Rust SDK](/es/sdks/rust)
* Soporte para equipos
* Gestión de claves de API en el panel.
* `onlyMainContent` ahora es `true` de forma predeterminada.
* Compatibilidad con webhooks y websockets para `/crawl`.

<div id="new-crawl-webhook">
  ## Nuevo webhook de Crawl
</div>

Ahora puedes pasar el parámetro `webhook` al endpoint `/crawl`. Esto enviará una solicitud POST a la URL que especifiques cuando el rastreo se inicie, se actualice y se complete.

El webhook ahora se activará para cada página rastreada y no solo para el resultado completo al final.

<CrawlWebhookCURL />

<div id="webhook-events">
  ### Eventos de webhook
</div>

Ahora hay 4 tipos de eventos:

* `crawl.started` - Se desencadena cuando se inicia el rastreo.
* `crawl.page` - Se desencadena por cada página rastreada.
* `crawl.completed` - Se desencadena cuando finaliza el rastreo para informarte que concluyó.
* `crawl.failed` - Se desencadena cuando falla el rastreo.

<div id="webhook-response">
  ### Respuesta del webhook
</div>

* `success` - Si el webhook logró rastrear la página correctamente.
* `type` - El tipo de evento que ocurrió.
* `id` - El ID del rastreo.
* `data` - Los datos extraídos (Array). Solo estará no vacío en `crawl.page` y contendrá 1 elemento si la página se extrajo correctamente. La respuesta es la misma que la del endpoint `/scrape`.
* `error` - Si el webhook falló, contendrá el mensaje de error.

<div id="scrape-endpoint">
  ## Endpoint `/scrape`
</div>

El endpoint `/scrape` actualizado ha sido rediseñado para mejorar la fiabilidad y la facilidad de uso. La estructura del nuevo cuerpo de la solicitud a `/scrape` es la siguiente:

```json
{
  "url": "<cadena>",
  "formats": ["markdown", "html", "rawHtml", "links", "screenshot", "json"],
  "includeTags": ["<cadena>"],
  "excludeTags": ["<cadena>"],
  "headers": { "<clave>": "<valor>" },
  "waitFor": 123,
  "timeout": 123
}
```

<div id="formats">
  ### Formatos
</div>

Ahora puedes elegir en qué formatos quieres el resultado. Puedes especificar múltiples formatos de salida. Los formatos compatibles son:

* Markdown (markdown)
* HTML (html)
* HTML sin procesar (rawHtml) (sin modificaciones)
* Captura de pantalla (screenshot o screenshot@fullPage)
* Enlaces (links)
* JSON (json)

De forma predeterminada, el resultado incluirá solo el formato markdown.

<div id="details-on-the-new-request-body">
  ### Detalles del nuevo cuerpo de la solicitud
</div>

La siguiente tabla detalla los cambios en los parámetros del cuerpo de la solicitud para el endpoint `/scrape` en V1.

| Parameter | Change | Description |
| --------- | ------ | ----------- |
| `onlyIncludeTags` | Movido y renombrado | Movido al nivel raíz y renombrado a `includeTags`. |
| `removeTags` | Movido y renombrado | Movido al nivel raíz y renombrado a `excludeTags`. |
| `onlyMainContent`| Movido | Movido al nivel raíz. `true` por defecto. |
| `waitFor`| Movido | Movido al nivel raíz. |
| `headers`| Movido | Movido al nivel raíz. |
| `parsePDF`| Movido | Movido al nivel raíz. |
| `extractorOptions`| Sin cambios ||
| `timeout`| Sin cambios ||
| `pageOptions` | Eliminado | No se necesita el parámetro `pageOptions`. Las opciones de raspado se movieron al nivel raíz. |
| `replaceAllPathsWithAbsolutePaths` | Eliminado | `replaceAllPathsWithAbsolutePaths` ya no es necesario. Ahora, cada ruta es absoluta por defecto. |
| `includeHtml`| Eliminado | agrega `"html"` a `formats` en su lugar. |
| `includeRawHtml`| Eliminado | agrega `"rawHtml"` a `formats` en su lugar. |
| `screenshot`| Eliminado | agrega `"screenshot"` a `formats` en su lugar. |
| `fullPageScreenshot`| Eliminado | agrega `"screenshot@fullPage"` a `formats` en su lugar. |
| `extractorOptions` | Eliminado | Usa el formato `"json"` en su lugar con el objeto `jsonOptions`. |

El nuevo formato `json` se describe en la sección [llm-extract](/es/features/extract).

<div id="crawl-endpoint">
  ## endpoint /crawl
</div>

También hemos actualizado el endpoint `/crawl` en `v1`. Consulta el cuerpo de la solicitud mejorado a continuación:

```json
{
  "url": "<string>",
  "excludePaths": ["<string>"],
  "includePaths": ["<string>"],
  "maxDepth": 2,
  "ignoreSitemap": true,
  "limit": 10,
  "allowBackwardLinks": true,
  "allowExternalLinks": true,
  "scrapeOptions": {
    // mismas opciones que en /scrape
    "formats": ["markdown", "html", "rawHtml", "screenshot", "links"],
    "headers": { "<key>": "<value>" },
    "includeTags": ["<string>"],
    "excludeTags": ["<string>"],
    "onlyMainContent": true,
    "waitFor": 123
  }
}
```
